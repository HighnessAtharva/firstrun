### B2. Which commits count

A commit counts only if all of these hold:

### B4. Identity and merging

Parse emails:

- `^([^@+]+)@users\.noreply\.github\.com$` → login.

- Take the newest commit sha of each identity (distinct lowercased email). Limit this to the top 100 identities by weight.
- Query `https://api.github.com/graphql` in batches of 50: `c{i}: object(oid:"&lt;hex&gt;"){... on Commit{author{user{login databaseId}}}}`, with `repository(owner,name)` taken from the clone URL. Validate that each oid is hex.
- Token: `GITHUB_TOKEN` or `GH_TOKEN`, else `gh auth token` (subprocess, 5 s timeout, never logged).

- Same normalized name: NFKD, accents stripped, casefold, punctuation removed, whitespace collapsed. Skip the name merge when the two identities have different known logins, or the name is generic (`root, admin, ubuntu, user, unknown, github, dev`).

- Name: the most-used git name. If it contains `@`, use the login. If there is no login, use `Contributor N`.

### B5. Recency-weighted file weight

```
decay(c)  = 2 ** (-(as_of - c.adate).days / 90)
n         = len(kept_files(c))
mass(c)   = decay(c) * min(1 + log2(n), 4)       # 1 file = 1, 2 = 2, 4 = 3, 8 or more = 4
share(c,f)= mass(c) / n                          # spread evenly over the commit's files
```

Why these numbers:
- **Half-life 90 days.** A quarter is the usual planning cycle. A one-year-old commit counts 6%, so people who left fade out and steady contributors stay.
- **Window 365 days.** Older commits weigh under 6%. Cutting them keeps the run fast.
- **Log cap.** A 250-file refactor counts at most 4 one-file fixes, spread thinly. No single commit can dominate.
- **Files, not lines.** Line counts need blobs, which the clone does not have.

Accumulate:
- `w[p][f]` per file.
- `dw[p][(repo, dir)]` for every ancestor dir, up to depth 6.

### B6. Areas: the "frontier" split (decided, replaces `features[].area` for the team)

Inputs:
- `file_w[(repo, path)]`, summed over all humans.
- The set of dirs present at `as_of` (`git ls-tree -r --name-only &lt;rev&gt;`).

A path whose dir no longer exists maps to its longest existing ancestor. If it has none, it goes to `rest`. That also handles renames.

```
DESCEND = 0.85; SPLIT = 0.22; MIN = 0.03; AREAS_MAX = 10 (single repo) | code 7 + docs 3 (docs repo)
descend(n): while n has a child c with W(c) &gt;= DESCEND*W(n): n = c       # skips src/, packages/x/src/, crates/
nodes = [descend(c) for c in children(root) if W(c) &gt;= MIN*T]; root-level files and small children go to rest
loop:
  n = heaviest node with W(n) &gt;= SPLIT*T and at least 2 child dirs with W &gt;= MIN*T
  if none or len(nodes) &gt;= AREAS_MAX: break
  replace n with [descend(c) for those children] + "n (other)" bucket if the remainder is &gt;= MIN*T, else the remainder goes to rest
keep the heaviest AREAS_MAX nodes; the rest go to rest
label = basename(n); if basename is in {src, lib, app, core, internal, pkg, main, source, packages, crates, docs, content}: use "parent/basename"
```

When `docs_repo` is set, run the frontier separately per repo: `repo:"code"` with up to 7 areas and `repo:"docs"` with up to 3. Shares are within each repo. People merge across both repos by login or normalized name. In a single repo, docs dirs compete as normal areas (for accuknox: `docs/use-cases`, `docs/getting-started`, and so on).

### B7. Per-area and per-person metrics

| Field | Formula |
|---|---|
| `area.share` | `W(area) / T(repo)` |
| `owners[].s` | person's weight in the area / `W(area)`, over all humans, with `others` aggregated |
| `bus` | smallest k such that the top-k owner shares sum to at least 0.5 (classic truck factor) |
| `single` | top share &gt;= 0.75, or only one person with share &gt;= 0.05 |
| `quiet` | `as_of - area.last` &gt; 180 days |
| `person.share` | person's weight / total human weight |
| `top` | the person's heaviest area |
| `top_share` | that area's weight / the person's total weight (including `rest`) |
| `commits`, `last` | raw counts and dates, shown to humans; ranking uses weights |

Why a truck factor and not the suggested "&gt;20% holders" count: with ten people at 10% each, the &gt;20% rule gives a bus factor of 0, which is wrong. Taking the fewest people who hold half the work stays meaningful at any team size.

Which people are listed:
- The top 12 by weight, and only those with share &gt;= 1.5% or at least 3 commits.
- Everyone else goes into `others`.
- Owners and runners-up from `next` are appended, up to 16 in total.

Edge cases:
- **One person:** 1 person, every area `single`. The UI says so plainly (D).
- **1 to 3 people:** normal map.
- **Hundreds of people:** top 12 plus `others`. Test this at 300.
- **History capped at 20,000:** if the oldest commit is newer than the window start, set `team.capped = true`.

`build_team(sources, as_of, hidden=set(), extra_bots=set(), token=None) -&gt; (team_json, ctx)`. The `ctx`, which is internal and never serialized, holds:
- `pid_of_sha[sha9]`
- `files_of_sha[sha9]`
- `dw`
- `recent_by_dir[(repo, dir)]`: the newest 20 human commits, as `(pid, date)`
- `last_toucher(repo, path) -&gt; (name, date)`
- `active(pid)`: true if the last commit is within 180 days
- `momentum`

## C. Top 10 prioritized items with rationale

**New module: `src/firstrun/nextup.py`**

`build_next(board, ctx | None, as_of, mom, changelog_recent) -&gt; dict`. Inputs are only what a board already holds (`cards`, `pages`, `features`, `release`) plus history. That makes new audits and the backfill share the same code.

### C1. Candidates

- Every non-`content` card, mapped by kind.
- Up to 10 extra `refresh` candidates: stale or unchecked pages not already in a refresh card, top by `relevant_since`. Their evidence is `page.evidence`.
- Join a refresh card to its page by path (the `Refresh &lt;path&gt;` title, or `cardPath` logic). Join features by `sha`.
- Join document clusters to all `features` with the same `area` and `covered == false`.
- Dedupe announces by cleaned subject; accuknox has "Add GCP organization onboarding guide" twice. Drop an announce whose sha already appears in a document item.

### C2. Score

All parts are in [0, 1]. `d(x)` means days between `as_of` and date `x`.

```
score = round(100 * (0.30*I + 0.25*U + 0.20*E + 0.15*J + 0.10*ease)),  ease: S=1, M=0.6, L=0.3

document cluster: I = 0.55 + 0.25*min(1, n/10) + 0.20*min(1, mom[area].commits/30)
                  U = 2**(-d(newest)/45)
                  E = min(1, n/5) * (1 if area_src == "scope" or any strong term else 0.85)
                  J = 1 if any feature.judge == "jev" else 0.6
document single:  I = 0.55 + 0.10*(has strong term)
                  U = 2**(-d/45)
                  E = 0.6 + 0.2*(strong term) + 0.2*(PR number)
                  J as above
refresh:          I = 0.45 + 0.25*entry(path) + 0.30*min(1, relevant_since/20)
                  U = 0.5*min(1, age_days/730) + 0.5*2**(-d(newest evidence)/90)
                  E = min(1, relevant_since/5)
                  J = 1 if judge == "jev" and status == "stale"; 0.6 if text only; 0.35 if unchecked
                  entry = 1 if the name matches readme|index|quickstart|getting[-_]started|install|introduction|overview, or path depth &lt;= 2
release:          I = 0.5 + 0.15*(not changelog_recent); U = 2**(-d(release.date)/30)
                  E = min(1, commits/10); J = 0.6
                  skip when commits == 0
announce:         I = 0.25; U = 2**(-d/21); E = 0.5 + 0.2*(PR); J = 0.4
quickstart:       I = 0.4 + 0.3*(README or quickstart-like page is stale/unchecked/aging)
                  U = 0.3; E = 0.3; J = 0.5
```

Why the weights are ordered this way:
1. **Impact first:** docs exist for readers.
2. **Urgency second:** users are trying new features now, and a stale page misleads every visitor today.
3. **Evidence third:** prefer what can be proven.
4. **Judged fourth:** a model read the page, versus a text match.
5. **Ease last:** a tie-breaker that favors quick wins without letting trivia outrank real gaps.

Hand-checked against real boards:

| Board | Item | Score |
|---|---|---|
| altimate-code | `workspace` cluster | 92 |
| dbt-core | `databricks` cluster | 85 |
| dbt-core | `_versions-contracts.md` refresh | 82 |
| accuknox | `Process-based-asset-access` refresh | 72 |
| altimate-code | YOLO single | 67 |
| (any) | announce | about 55 |
| accuknox | `net-seg` refresh | 50 |

**Effort rules** (`effort_why` gives the rule in words):

| Kind | S | M | L |
|---|---|---|---|
| refresh | `relevant_since` &lt;= 3 | &lt;= 10 | more than 10 |
| document cluster, own page exists | | n &lt;= 6 | otherwise |
| document cluster, new page | | otherwise | n &gt;= 8 |
| document single | has `closest_page` | otherwise | |
| release, announce, quickstart | always | | |

For refresh, an `ancient` page moves up one level, capped at L.

**Order and caps:**
- Sort by score descending, then newest evidence, then title.
- Caps inside the top 10: refresh 5, document 5, announce 2, release 1, quickstart 1.
- Overflow continues at rank 11 and later. Keep at most 30 items.

### C3. Text, from real fields only

**Titles:**
- Cluster with its own page: "Add the new {area} changes to {basename}".
- Cluster with no page: "Write a page for {area}".
- Single: "Document: {Clean subject}".
- Refresh: "Update {page title}", with `path` set.
- Release: "Publish the {name} release notes".
- Announce: "Announce: {Clean subject}".
- Quickstart: "Prove the quickstart still runs".

**Rationale** (one sentence, always citing a SHA, a date or a count):
- Refresh: "Last edited {date}. Since then {k} commits changed code on its topic, newest {sha} on {date}, and Jev expects the page is now wrong." The last clause is "Jev did not read it" when Jev did not run.
- Single: "{sha} shipped "{subject}" on {date} in #{pr}, and Jev read {closest_page} and found it does not explain it."
- Release: "{n} commits landed between {prev} and {name} ({date}), and no changelog file changed in the last 60 days."
- Cluster: as in the schema example.

**why_now:**
- Document and announce: "Shipped 4 days ago", "Shipped 3 weeks ago", "Shipped 2 months ago".
- Refresh: "Code moved 32 days ago under a page last edited 680 days ago".
- Release: "v2.0.5 shipped 3 days ago".
- Quickstart: "A text audit cannot prove a run".

### C4. Owner suggestion

```
For each item, collect:
  code_dirs: parent dirs of the product files in its evidence commits (found by sha in history), plus feature.files
  docs_dir:  parent dir of path (refresh), closest_page (document), README (quickstart)
A(p) = share of the item's evidence commits authored by p
C(p) = sum over d in code_dirs of dw[p][d] / max over q of the same     (0 for everyone if that max &lt; 1.0)
D(p) = dw[p][docs_dir], plus the file itself, / max over q              (same floor)
aff  = a*A + b*C + g*D, with (a, b, g):
       document (.50, .35, .15)   refresh (.25, .30, .45)   announce (.80, .20, 0)
       quickstart (0, 0, 1)
       release: if the newest tag's tagger is human, that person gets aff 1; otherwise A over the release range
eligible = active in the last 180 days
owner only if top aff &gt;= 0.25
otherwise owner = null and fallback = last human toucher of path or evidence files:
       "Last touched by {name} on {date}", else "No one touched these files in the last year"
```

**Load balancing** applies to the top 10 only, in rank order:
- `cap = max(2, ceil(10 / n_eligible) + 1)`, where `n_eligible` counts people with aff &gt;= 0.25 on any top item. There is no cap when `n_eligible &lt;= 1`.
- The pool is the eligible people with `aff &gt;= 0.6 * top_aff`. Pick the first one in the pool whose load is under the cap. If none, pick the top expert anyway: the cap is soft.
- Set `balanced = true` when the pick is not the top expert.
- `runner_up` is the best other eligible person with aff &gt;= 0.15.

**Reason** (the strongest term wins):
- A: "{name} shipped it in #{pr}" or "{name} wrote {k} of the {n} changes behind it".
- C or D: "{name} made {k} of the last {m} commits to {dir}/". `dir` is the deepest ancestor with at least 5 window commits. `m = min(20, commits to dir)`.
- Release: "{name} tagged {tag}".

Each item's `area` is the area whose path is the longest prefix of the item's primary file.

### D1. Choice of visualization

I rejected these options:
- **Chord diagram:** unreadable to a stranger and bad at 375 px.
- **Classic Sankey:** small nodes make labels collide.
- **Avatar bubbles:** imprecise.
- **Swimlane:** reads like a log.

## E. Backfill and CI

### E1. Backfill script: `scripts/audit_team_backfill.py` (same style as `audit_cost_estimates.py`)

Options:
- Default is a dry run that prints, per board: people, areas, the top 10 titles, owner, score.
- `--apply` writes.
- `--only &lt;id&gt;`, `--force` (recompute even if `team` exists), `--no-github`.

For each `docs/audits/audit-*.json` where `mode != "sitemap"`:
1. Clone with `audit.clone` into a temp dir.
2. `rev = history.head`, or `git rev-list -1 --before=&lt;generated_at&gt; HEAD`.
3. `commits = read_history(repo, rev)` and `tags = read_tags`. Get the paths at `rev` with `ls-tree`. Do the same for `docs_repo`.
4. `as_of = generated_at`.
5. `mom = audit.momentum(commits, as_of, board["features"])`. Compute `changelog_recent` the way `_audit` does.
6. Build `team` and `next`.
7. Set `b2 = {**b, "team": ..., "next": ...}`. Assert that `set(b2) - set(b) &lt;= {"team", "next"}` and that every other value is equal.
8. Write compact JSON exactly like `publish()`. Never touch `index.json`, `cards`, `summary` or receipts.
9. Apply opt-outs (F). Remove the temp dir in `finally`.

No Jev call happens, so no counts change.

### E2. New audits

**`_audit`:**
- Add `team: bool = True`.
- After `build_cards`, wrap a `neatlogs.trace("audit.team", kind="TOOL")` in `try/except Exception`. On failure: no `team`, `next` built with `ctx=None`, and the span output records only the exception type.
- The trace output holds counts only, and `_trace_output` adds `next` titles and scores, never names.

**Opt-out checks:** `FIRSTRUN_TEAM=0` gives `disabled: "env"`. A repo file gives `disabled: "repo"` (F).

**CLI:** `firstrun audit --no-team`.

**Intake workflow:** `GH_TOKEN` already reaches `scripts/audit_intake.py`. Pass `team=fields["team"]`.

**Example workflow:** add `GH_TOKEN: ${{ github.token }}` to the audit step in `examples/github-action/firstrun-audit.yml`.

**Output changes:**
- `to_markdown` adds "## What to Ship Next" (the top 10, with "Suggested: Name") and "## Who Works on What" (area → top owners).
- `issue()` uses `next.items[:10]` when present (fallback: cards, skipping `content`). Each line is `- [ ] **{title}**{ (`path`)}. {rationale} Suggested: {name} ({login}).` Write logins without `@` so nobody gets pinged.

**Failure behavior:** the token lookup, GraphQL, the opt-out file read and team math each fail closed to "no team" or `source: "git"`. The audit never fails because of them. The repo opt-out read is `git show &lt;rev&gt;:.github/firstrun.yml`, then `.firstrun.yml`, with a 30 s timeout. A missing file is fine.

## F. Privacy and ethics

**What is shown:**
- The git author name, already public in commits and already on boards via `features[].author`.
- The GitHub login and the avatar from GitHub.
- Commit counts and dates.

**What is never shown:**
- Emails, whether raw or hashed: hashes of emails can be reversed against Gravatar-style lookups.
- Person ids are `p1` to `pN`.

`team.sanitize(doc)` runs in `publish()` and `intake.validate()`:
- Drop any string field matching `[\w.+-]+@[\w-]+\.[\w.-]+`.
- Enforce the login regex and an integer `gh`.
- Cap list sizes: people 16, areas 12, items 30.
- Drop unknown keys in `team`.

**Opt-outs:**
- Run level: `--no-team` or `FIRSTRUN_TEAM=0`.
- Repo owner: put `team: false` in `.github/firstrun.yml` or `.firstrun.yml` (regex parse, no YAML dependency).
- Requester: the issue template gets a checkbox, "Leave out the team map (contributor names and avatars)". `intake.parse_issue` returns `team: False` when it is ticked.
- Person: add `"sha256:&lt;hex of lowercase login, or normalized name&gt;"` to `hidden` in `docs/audits/team-optout.json` (`{"v":1,"hidden":[],"bots":["fa-assistant"]}`), then run the backfill with `--force --only`. A hidden person's weight moves into `others`, and they are never suggested. The file stores hashes so it does not publish a list of who opted out.

**Wording:**
- The team note: "Built from public commits in the last 12 months. Suggestions, not assignments: anyone can pick up any task."
- Labels say "Suggested", never "Assigned".

**Private repos:**
- They stay local as today, and `team` is computed for the owner's `runs/` report.
- `audit-submit` strips `team` and the owner, runner-up and fallback fields from `next` unless `--with-team` is passed, and it says so in its prompt.

**README:** add a "Team map and privacy" subsection under section 7.

**`docs/known-limits.md`:**
- Identities merge by login only when a token is available.
- Co-author trailers are ignored. AI co-author trailers are common, and human pairing trailers are rare.
