## Credentials

There are three kinds:

- **SDK project key** (`NEATLOGS_API_KEY`): sends traces, works with the SDK prompt functions, and authenticates the MCP server. It cannot read through the Public API.
- **Service-account token**: for CI and scripts. Create it in **Settings → Service Accounts**.
- **Human OAuth**: `neatlogs auth login`. Some write operations accept only this.

Every Public API request uses the same base and headers:
```http
https://app.neatlogs.com/api/v1/public/...
Authorization: Bearer &lt;service-account-token or OAuth token&gt;
x-project-id: &lt;project-uuid&gt;
idempotency-key: &lt;uuid4&gt;   # required on every mutation; rejected on reads
```

- **Scopes:** `observability:read/write`, `evaluation:read/write`, `configuration:read/write`, `context:read`.
- **Response shape:** success is `{success, requestId, data}`. Errors use `application/problem+json`.
- **Pagination:** cursors expire after 15 minutes. Trace lists take a `limit` of 1 to 50.

## Features

"SA" means a service-account token works. "OAuth only" means it needs a human CLI login.

| Feature | How to set it up | Exact call | Limits and gates |
|---|---|---|---|
| Sessions | SDK | `@neatlogs.span(kind="WORKFLOW", session_id=...)`, `neatlogs.trace(name, session_id=...)`, or `with neatlogs.identify(session_id=, parent_session_id=, session_custom_fields={...})` | If you omit it, `session_id` equals `trace_id`. `identify()` does not carry across processes. |
| End user and metadata | SDK | `trace(..., end_user_id=str(uid), end_user_metadata={"plan":"pro"})` or the same arguments on `identify()` | Set it on the root span only. It is not an `init()` argument. Filter with `metadata:plan`. |
| Operator ID and tags | SDK | `init(user_id=..., tags=[...])`. Extra `wrap()` kwargs become `neatlogs.workflow.&lt;key&gt;`. | Tags apply to the whole process. |
| Change trace tags or name later | API (SA) | `PATCH /traces/{traceId}` with `{"expectedRevision":int,"tags":[...≤10],"traceName":"..."}` | Needs the `public-api-mutations` capability. |
| Trace feedback (rating) | **API, OAuth only** | `POST /traces/{traceId}/feedback` with `{"rating":-100..100,"accuracy":"≤50 chars","comment":"...","expectedResponse":"...","issueTypes":[≤20]}` | No SDK function exists. SA tokens are not accepted. |
| Span thumbs up or down | API, OAuth only | `PUT /traces/{t}/spans/{s}/feedback` with `{"vote":"up"\|"down","note":"..."}` | Also in the dashboard ("Voting"). |
| Bulk feedback | API, OAuth only | `POST /feedback/bulk` with `{"items":[{"action":"trace_feedback.create","itemKey":"k1","target":{"traceId":"..."},"body":{...}}]}` | 1 to 100 items. Also `span_feedback.set` and related actions. |
| AI evaluator definition | API (SA) or CLI `evaluators create --body-stdin` | `POST /evaluators` with `{"name","type":"llm_judge"\|"agent_judge","systemPrompt"≤20000,"modelProvider","modelName","maxBudgetUsd"≤100,"maxToolCalls"1-50 (default 12),"reasoningEnabled","outputSpec":[{"key","label","scoreType":"boolean\|numeric\|categorical\|text","options","required"}],"toolGrants":[{"provider":"neatlogs_mcp\|composio\|http_get\|custom_mcp","toolName","config"}]}` | — |
| Run an evaluator on one trace | OAuth only | `POST /evaluators/{id}/runs` with `{"traceId","spanId"}` and `/playground` | Gated by `tier-c-compute`, which is disabled in production. |
| Evaluation (scheduled or online) | API (SA) or CLI `evals create` | `POST /evaluations` with `{"name","type":"human"\|"ai","traceSource":"existing"\|"future","sendFrequency":"immediate\|batched\|manual","batchSchedule":"24h\|1d\|1w","samplingRate":1-100,"dailyLimit","startsAt","endsAt","traceFilter":{workflowName,tags,status,span_names,span_types,detectionNames,sessionIds,endUserIds,cost_min/max,latency_min_ms/max_ms,...}}` | Known bug: a future collection can miss traces that arrive after the last matcher pass. |
| Evaluation form | API (SA) | `PUT /evaluations/{id}/form` with `{"name","questions":[{"answerType":"rating\|linear_scale\|multiple_choice\|...","questionText","sortOrder","options"}]}` | **The schema has no field to assign an AI evaluator to a question.** The docs show this only in the dashboard. |
| Activate, launch, dispatch | Activate and launch are OAuth only. Dispatch works with SA. | `POST .../activate` with `{"reviewerUserIds":[...],"reviewDuration":"1h","maxItems","maxAssignments"}`. `POST .../batches/dispatch` with `{"maxItems"≤1000,"maxAssignments"≤10000}`. | — |
| Read eval results | API (SA) | `GET /evaluations/{id}/responses`, `.../progress`, `.../batches/{b}/report`, `/traces/{t}/evaluations`, `/evaluations-stats` | CSV and JSON export are available. |
| Datasets | Not available | — | The Experiments page says "Coming soon". Only classifier datasets exist, and those are disabled. |
| Prompt management | SDK (project key) or API (SA) | `neatlogs.get_prompt(name, label="production" \| version=3)`, `aget_prompt`, `list_prompts`, `create_prompt(name, prompt=..., type="chat", labels=[...])`, `update_prompt(name, version, new_labels=[...])`, `save_as_version(prompt_name, messages, labels, commit_message)`, `delete_prompt`, `remove_tag`. API: `POST /prompts` and `PUT /prompts/{id}/label`. | Reads use a 60 s cache with stale-while-revalidate. `mask=` does not apply to prompt calls. |
| Prompt playground | Dashboard only | — | Needs your own provider keys in Settings → AI Providers. |
| Alerts | API (SA) or CLI `alerts create` | `POST /alert-rules` with `{"name","ruleType":"threshold\|per_event\|compound\|ingestion_health\|metric_threshold","severity","detectionId","thresholdCount","windowMinutes","cooldownMinutes","conditions":[{"detection","operator","threshold"}],"metricName":"cost\|latency\|error_rate\|tokens_total\|trace_count\|tool_failure_rate\|detection_rate...","metricAggregation":"sum\|avg\|p95\|p99\|count\|rate...","metricOperator","metricThresholdValue","silenceMinutes","channelMask":{"email","slack","webhookIds":[≤1]}}`. Test: `POST /alert-rules/{id}/test`. | — |
| Webhooks | API (SA) | `POST /webhooks` with `{"name","destinationUrl","eventTypes":["alert.threshold_breach","notify.eval_completed",...],"secret"}` | Fire history: `GET /alert-history`. |
| Detections | API (SA) or CLI | `POST /detections` with `{"displayName","groupId","type":"regex"\|"conditional"\|"pii"\|"classifier","config":{...},"runOn":{"frequency":"trace\|span_type\|span_name","span_names":[...]},"threshold"}`. Reads: `/detections/{id}/hits` and `/trends`. | `generate`, `preview`, suggestions and backfill are OAuth only and `tier-c-compute`, so disabled. Built-in classifiers are only `jailbreaking`, `nsfw`, `hate` and `refusals`. |
| Investigate | **Dashboard only** | — | No Public API endpoint exists. The MCP server reads only the investigations attached to Fixes. The neatlogs.com homepage advertises `neatlogs ask`, but the docs command reference does not list it. |
| Fixes | Dashboard, or the MCP tools `triage_*` | — | Dispatch needs a connected GitHub repository. Only Cursor Cloud Agents are supported today. |
| Query traces, cost and analytics | API (SA, or the legacy key) or CLI | `GET /traces?from&amp;to&amp;status&amp;workflowName&amp;sessionId&amp;limit&amp;cursor`, `GET /traces/{id}/spans`, `GET /traces/{id}/export`, `POST /analytics/cost` with `{"from","to","filters":{"workflowNames","statuses":["OK","ERROR"],"sessionIds","detections"}}`. | MCP server | Project SDK key | URL `https://ingest.neatlogs.com/mcp`, header `Authorization: Bearer &lt;project key&gt;`. Tools: `search_traces`, `get_trace_context`, `list_detections`, `get_detection_trend`, `triage_*`, `log_trace`, `whoami`. | — |
| SDK self-check | SDK | `python -m neatlogs doctor --local --json`, then `--probe --json` | The probe reads its own test trace back. |

## CLI (`neatlogs-cli`)

Install with `npm i -g neatlogs-cli@0.2.1`. It needs Node 22 or 24. The binary is `neatlogs`.

Command groups: account, alerts, analytics, api, api-keys, auth, billing, classifiers, coding-tools, comments, completion, credential-migrations, credentials, detections, evals, evaluators, feedback, filters, groups, guest, guest-links, imports, incidents, ingest-credentials, integrations, mcp, notifications, orgs, profile, projects, prompts, schema, service-accounts, sessions, sharing, skills, traces, usage, version, webhooks, whoami.

Useful subcommands:
- **feedback:** `feedback create --trace &lt;id&gt; --body-stdin`, plus `span-set` and `bulk`.
- **evals:** `evals create`, `form set`, `activate`, `batches dispatch`, `schedules update --batch-schedule 1d`, `responses`, `stats --period 7d`.
- **traces:** `traces list --all --max-items 500 --json`, `traces semantic-search`, `traces update-metadata`.
- **analytics:** `analytics cost` and related commands.
- **any operation:** `neatlogs api &lt;operationId&gt; --param --query --body-stdin`.

For CI, run `neatlogs --host https://app.neatlogs.com --credential-source token --project &lt;uuid&gt; ...` with `NEATLOGS_TOKEN` set.

## Plan Limits From the neatlogs.com Pricing Page

The hackathon lifted these, but here they are:
- **Pro:** 1M spans per month, unlimited Investigations and AI evals, 90-day retention.
- **Starter:** 5,000 AI evals, 50 Investigations, 30-day retention.

Separately, service-account administration and token minting share one rate-limit bucket. It holds 10 requests and refills at 10 per hour.
